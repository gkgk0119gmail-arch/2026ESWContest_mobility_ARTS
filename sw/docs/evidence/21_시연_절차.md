# 21. 2차 방어 시연 — 현장 시연과 영상 촬영 절차

> 프로그램: `sw/scripts/demo/moza_demo.py` (데스크톱), `sw/scripts/demo/pi_demo_up.sh` (라즈베리파이).
> 장면과 판단 코드는 20번 문서와 같다 (CARLA 0.9.16, 빙판 위 정지 차량, SLIP_ENVELOPE).

## 구성

| 장비 | 하는 일 |
|---|---|
| 데스크톱 (RTX 3090, CARLA 0.9.16) | CARLA, Moza 휠·페달 입력, 화면, 녹화, 1차 카메라(선택) |
| Moza R3 휠 + SRP 페달 | 사람이 운전. 휠은 중앙 복귀 스프링, 탭 때 짧은 충격, 빙판 확정 때 진동 |
| 라즈베리파이 5 | 2차 방어 판단 — **격리 코어**(코어 3, SCHED_FIFO — 안전 전용 RTOS 대체)에서 20 ms 마다 탭 판단·정지 거리·제동 명령. '메인 프로그램' 대역이 심장박동을 보낸다 |

데스크톱→파이 방향을 막는 망(캠퍼스)에서도 되도록 **파이가 먼저 인사 패킷**을 보내고 데스크톱은 그 길로 답한다.
캠퍼스 와이파이에서 왕복 지연 중앙 4.8 ms, 99 % 9.4 ms (200회). 0.2 s 까지의 무응답은 마지막 명령을 유지하고, 넘으면 화면에 '안전 전용 RTOS 응답 없음'.
사람이 운전하는 운전석 시점에서 시뮬레이션은 실시간의 0.996 배로 돈다 (녹화를 켜면 느려지지만 영상은 시뮬레이션 시간으로 저장된다).

## 실행

```bash
# 1) 데스크톱: CARLA
cd ~/CARLA && ./CarlaUE4.sh -carla-rpc-port=2000 -quality-level=Epic -RenderOffScreen -nosound &
# 2) 파이: 격리 코어 2차 방어 + 메인 프로그램 대역 (데스크톱 IP 를 준다. 현장 직결이면 고정 IP)
sw/scripts/demo/pi_demo_up.sh <데스크톱IP>
# 3) 데스크톱: 시연 프로그램 (사람이 운전)
python3 sw/scripts/demo/moza_demo.py --island listen:5700 --pi-main listen:5701 --fullscreen
#    자동 녹화(시뮬레이션 영상):  --auto --view chase --show-ice --defense off|on [--kill-at 14] --record out.mp4
```

키: **C** 휠 영점 · **D** 2차 방어 켜기/끄기(장면 다시 시작) · **A** 크루즈 · **R** 다시 · **K** 파이 메인 프로그램 죽이기 · **V** 운전석/추적 시점 · **I** 빙판 구역 표시 · ESC 끝

## 1차 방어 장면 — RealSense 로 빙판 사진 비추기

```bash
python3 sw/scripts/demo/realsense_primary.py            # RealSense RGB 자동 탐지 (pyrealsense2 또는 UVC). --source cam:N 으로 직접 지정
```
- 태블릿·모니터·출력물에 RSCD 빙판 사진과 마른 노면 사진을 번갈아 띄우고 RealSense 로 비춘다. 화면에 노면 분류 확률·위험도가 실시간으로 나오고,
  빙판이면 '블랙아이스 감지 — 감속하세요' 배너. 경고 계산(위험도 융합, 기온 −3 °C 맥락에서 문턱 0.60)은 실제 1차 방어와 같다.
- **모델은 흐림에 약하다.** RSCD 360×240 사진을 두 배로 키워 흐려지자 빙판 확률이 88 % → 8 % 로 떨어졌다. 사진을 크고 선명하게 띄우고,
  카메라를 가까이 대고 초점을 확인한다. +/- 키로 판정 영역(빨간/흰 네모)을 비친 사진 크기에 맞춘다. 화면 무아레가 생기면 출력물이 낫다.
- 카메라 없이 확인: `--source <사진 폴더> --headless --record out.mp4` — RSCD 빙판 4장은 블랙아이스 88 ~ 96 %로 경고, 마른 노면 4장은 경고 없음.

### RealSense → CARLA 연동 (1차 방어가 시뮬레이션 차를 감속)

```bash
# 파이: RealSense 판정을 데스크톱으로 보낸다 (파이 → 데스크톱 방향)
python3 sw/scripts/demo/realsense_primary.py --send <데스크톱IP>:5702
# 데스크톱: 시연 프로그램이 판정을 받는다
python3 sw/scripts/demo/moza_demo.py --island listen:5700 --pi-main listen:5701 --primary listen:5702 --fullscreen
```
- 운전자가 액셀을 밟고 달리는 중에 RealSense 로 빙판 사진을 비추면, 경고가 3 프레임 연속 나올 때 확정한다.
  그 순간 경고음·휠 진동·주황 배너 '1차 방어 — 전방 블랙아이스 감지 · 자동 감속 30 km/h'가 나오고, 시스템이 가속을 끊고 30 km/h 까지 제동한다 (`--primary-kph`).
  운전자가 액셀을 계속 밟아도 그 장면이 끝날 때까지 감속이 유지된다. R 을 누르면 다시 시작.
- 1차 방어만 보여 줄 때는 D 로 2차 방어를 끈다 (탭이 섞이지 않게).

### 장면 기본값 (2026-10-27 촬영 연습 뒤)

| 항목 | 값 | 이유 |
|---|---|---|
| 출발점 → 빙판 | 100 m (`--patch-ahead`) | 빙판 전 구간이 길어 지루하다는 의견. 자동 녹화는 80 km/h 로 달리며 시작(`--start-kph`) |
| 빙판 → 앞차 | 145 m (`--obstacle-in`) | Town04 직선 안에 들어가야 한다 (늘리면 커브에서 가드레일 충돌) |
| 빙판 마찰 | friction 0.3 → μ 0.21 | 80 km/h 정지 거리 ≈ 125 m 로 직선 안에서 ON 이 설 수 있게 |
| 속도 | 80 km/h, 최고 80 (`--max-kph`) | 100 km/h 는 빙판 정지 거리 ≈ 280 m 로 장면이 직선에 안 들어간다 |
| 결빙 취약 구간 | 빙판 5 m 앞부터 (`--zone-before`) | 첫 탭이 빙판 위에서 나오게 |
| 브레이크 지점 | 앞차 65 m (`--brake-cue`) | 도로 위 빨간 선 'BRAKE HERE' + 노란 '브레이크!' — OFF/ON 같은 곳에서 밟는다 |

- **OFF = 지금 차의 자동 긴급 제동(AEB)**: 같은 판단 코드가 마른 노면 μ 로 제동 시점을 잡는다. 화면에는 '기존 자동 긴급 제동'으로만 쓴다.
- **ABS·ESC 대역** (CARLA 차에는 없다, OFF/ON 똑같이): 빙판 위 브레이크 상한 0.4(`--abs-cap`, μ 0.16 에서 0.3 과 1.0 의 감속이 1.57 vs 1.60 m/s²), 요 각속도 감쇠(`--esc 0.93`).
  넣기 전에는 탭 뒤 작은 흔들림이 자라 ON 이 돌다가 가드레일에 부딪혔다 (사람 운전 37 km/h).
- **미끄러짐 표시**: 빙판 위 제동 중 빨간 '바퀴 미끄러짐 — 밟아도 안 섭니다', 실제 감속 g, 타이어 소리, 휠 진동.
- **제동 시작 이유**: ON 이 처음 제동할 때 '앞차 ○ m · 정지에 ○ m 필요 → 지금 제동' 5 s.
- 자동 운전자(`--auto-driver evade`): 브레이크 지점에서 풀 브레이크 + 왼쪽으로 1.2 s 조향. `--assist-steer` 는 조향만 자동, 페달은 사람.
- 결과 판정: 앞차에 부딪히면 '충돌 (앞차)', 벽이면 '벽 충돌 (장면 이탈)'.

### 화면 녹화본 (`sw/media/clips/`, 데스크톱 x11grab, 실시간)

| 파일 | 내용 | 결과 |
|---|---|---|
| `screen_2nd_off_v4.mp4` | 2차 방어 OFF (기존 자동 긴급 제동만) | 앞차 20 km/h 충돌 |
| `screen_2nd_on_v4.mp4` | 2차 방어 ON — 빙판 시작점 탭 μ 0.21 → 즉시 예비 제동 | 앞차 28.5 m 앞 정지 |
| `screen_1st_photo_v3.mp4` | 1차 방어 — **RealSense 대신 RSCD 빙판 사진 파일을 같은 판정 코드에 넣은 것** (`--primary-label '노면 사진 입력'`), 2 s 에 경고 → 78→29 km/h | 앞차 50 m 앞 정지 |

1차 방어 영상을 실제 RealSense 로 다시 찍으려면: 사진을 녹화 **전부터** 비추고 `--primary-after 2 --patch-ahead 160` 으로 녹화한다 (80 km/h 면 빙판까지 4 s 라 그때 비추면 늦다).
v1~v3·photo_v1~v2 는 이전 설정 녹화본으로 남겨 둔다.

## 현장 시연 순서 (한 판 3~5 분)

1. **휠 영점** — 휠 로고를 똑바로 두고 C.
2. **2차 방어 OFF** (D 로 맞춘다). 운전자에게: "60 km/h 로 달리다가 앞에 차가 서 있으면 평소처럼 브레이크를 밟으세요."
   운전석 화면에는 빙판이 보이지 않는다 (블랙아이스). 평소 감각(40 ~ 60 m 앞)으로 밟으면 미끄러져 충돌한다.
3. **2차 방어 ON** (D). 같은 지시. 결빙 취약 구간에 들어서면 '노면 확인 탭'(휠 충격) → 빙판이면 경고음·진동·배너
   "빙판 감지 μ 0.15 — 정지에 ○○ m 필요". 운전자가 일찍 밟으면 그대로 서고, 계속 가속하면 시스템이 가속을 막고, 늦으면 필요한 순간에 시스템이 밟는다.
4. **고장 격리** — 빙판 경고가 뜬 뒤 K. 파이의 메인 프로그램 대역이 실제로 SIGKILL 된다.
   화면에 '파이 메인 프로그램 정지 — 2차 방어는 격리 코어에서 계속 동작'. 격리 코어는 카메라·지도 입력을 버리고(축소 모드) 이미 잰 μ 로 제동 판단을 계속한다. 대역은 20 s 뒤 다시 뜬다 — 그동안 2차 방어는 축소 모드(지도·카메라 입력 없음, 새 탭 없음)라 패널이 "동작"으로 돌아온 뒤 다음 판을 시작한다.
5. 필요하면 V(추적 시점) + I(빙판 표시)로 관객에게 빙판 위치와 정지 거리를 보여 준다.

**주의** — 결과를 아는 사람이 첫 판(OFF)에서 일부러 아주 일찍 밟으면 충돌하지 않는다. 처음 해 보는 사람이나 팀원이 평소처럼 운전한다.

## 영상 촬영

- **시뮬레이션 영상**: `--auto` 세 편(OFF → ON → ON + 14 s 에 메인 프로그램 KILL)을 녹화해 이어 붙인 것이 `sw/media/clips/demo_2nd_defense.mp4` 다.
  자동 녹화 결과: OFF 30 km/h 충돌, ON 4.1 m 앞 정지, ON + KILL 4.1 m 앞 정지.
- **Moza 직접 운전 영상**: 운전자와 화면이 함께 보이게 촬영한다. 위 현장 순서 2 ~ 4 를 그대로 찍는다.
  화면 녹화를 따로 남기려면 `--record` 를 켠다 (사람 운전은 녹화 중 실시간보다 느려질 수 있다 — 화면 녹화는 OBS 로 따로 하는 편이 낫다).

## 결선 현장 연결 (2026-10-30 연습으로 확정)

**랜선 직결 — 파이 랜 포트 ↔ 데스크톱 본체 뒤 위쪽 랜 포트(Intel I210).** 아래쪽 포트는 운영체제가 못 본다.
- 데스크톱 랜 포트에는 원래 고정 주소가 자동으로 붙는다 — 손댈 것 없음 (원격으로는 네트워크 설정 권한도 없다).
- 파이는 그 대역 안의 주소를 가진 `venue-wired` 프로필(게이트웨이 없음, 자동 연결 끔)을 쓴다. 연구실 주소·계정은 저장소 밖 `sw/scripts/demo/venue.env`(.gitignore)에 둔다.
- 파이의 `stm32-link`(공유 모드)는 자동 연결을 껐다 — 켜져 있으면 파이가 주소를 나눠 주는 서버가 된다.
- 링크가 안 잡히면 파이에서 `sudo ethtool --set-eee eth0 eee off` 후 선을 다시 꽂는다 (`venue_pi.sh` 가 자동으로 한다).

| 연결 | 왕복 지연 | 손실 | 2차 방어 ON |
|---|---|---|---|
| 랜선 직결 | 0.18 ms | 0 % | 28 m 앞 정지, 무응답 0 |
| 폰 핫스팟 (iPhone, 두 기기 모두 접속) | 평균 1.3 s, 최대 2.8 s | 3~90 % | 2.3 s 무응답 → 35 km/h 충돌 |

폰 핫스팟·USB 와이파이 동글은 데스크톱 인터넷용으로만 쓴다(시연에는 인터넷이 필요 없다).

**켜는 순서**: ① 랜선 연결 ② 파이 `sw/scripts/demo/venue_pi.sh` — 같은 망을 훑어 SSH 호스트 키로 데스크톱을 찾고(mDNS 는 도커 주소를 줄 때가 있어 쓰지 않는다) 격리 코어·메인 대역·RealSense 를 켠다
③ 데스크톱 `sw/scripts/demo/venue_desktop.sh [auto off|auto on|first]` — CARLA 가 꺼져 있으면 켠다.
2026-10-30 랜선 점검: 자동 OFF 20 km/h 충돌, ON 28.2 m 앞 정지, ON + 6 s 에 파이 메인 KILL 28.4 m 앞 정지 — 셋 다 무응답 0. RealSense 화면·위험도가 데스크톱 패널에 표시되고 왕복 0.3 ms.

## 결선 시연 대본 (2026-10-30 확정)

| 장면 | 실행 | 사람이 하는 일 | 확인한 결과 |
|---|---|---|---|
| ① 1차 방어 | `venue_desktop.sh first` (자동 직진 80 km/h) | RealSense 에 아이패드 블랙아이스 사진(대각선 줄무늬)을 '빙판까지 150 m' 이상 남았을 때 비춘다 | 8.4 s 감지 → 빙판 31.6 m 앞 정지. 마른 노면 사진이면 경고 0, 빙판에서 충돌 |
| ② 2차 방어 OFF/ON | `venue_desktop.sh assist` (조향 자동, 페달 사람) — D 로 OFF/ON, R 다시 | 액셀 끝까지, 빨간 선 'BRAKE HERE'에서 브레이크 → 조향이 자동으로 옆 차선으로 피한다 | 자동 점검: OFF 피하다 미끄러져 17 km/h 충돌, ON 28.6 m 앞 정지, 벽 충돌 없음 |
| ③ 고장 격리 | ② 의 ON 중 빙판 경고 뒤 K | — | 파이 메인 강제 종료 후에도 28.4 m 앞 정지 |

1차 방어의 제동 여부는 **RealSense 판정만**으로 정한다 (CARLA 카메라·2차 방어·빙판 위치를 섞지 않는다). 2차 방어 장면은 RealSense 를 받지 않는다(카메라가 못 본 상황).
**말할 것**: "같은 조건에서 비교하려고 회피 조향은 매번 똑같이 자동으로 넣었고, 브레이크는 제가 직접 밟습니다. 우리 시스템은 조향에는 개입하지 않고 제동 시점만 바꿉니다." — 운전자가 핸들을 따라 움직여도 되지만 자동임을 먼저 밝힌다.
ESC 대역은 운전자가 꺾은 만큼(빙판 마찰 한계 안)의 회전은 두고 넘는 회전(스핀)만 줄인다 — 빠를 때는 덜 돌아 미끄러지고 느릴 때는 꺾은 대로 돈다.

## 정직하게 밝힐 것

- 2차 방어 판단은 STM32 가 아니라 **라즈베리파이 격리 코어**에서 돈다 (보드가 없다). 같은 C 코드다.
- 운전석에서 느끼는 '툭'은 실차에서는 몸으로 느끼는 감속이다. 시뮬레이터에서는 휠 충격으로 대신한다.
- 결빙 취약 구간 위치는 시나리오가 정한 것이다. 1차 카메라는 이 장면에서 빙판을 거의 못 본다 (20번 문서).
- 메인 프로그램 대역은 실제 메인 프로그램(1차 맥락·브리지)이 아니라 심장박동만 보내는 대역이다.
