# 발표 근거 지도 — 어떤 주장에 어떤 자료를 쓰나

발표 흐름을 정하는 것은 팀 몫이다. 이 문서는 **"이 주장을 하려면 이 자료를 띄워라"** 만 정리한다.
서류(10/30) · 발표(11/6) 준비할 때 자료를 찾아 헤매지 않게 하는 것이 목적이다.

기준 2026-09-21 04:15. 근거 파일은 전부 `logs/carla_demo/정리/` 와 `logs/carla_demo/figures/` 에 있다.

---

## 1. 문제 정의 — 왜 블랙아이스인가

| 주장 | 자료 | 수치 |
|---|---|---|
| 카메라만으로는 못 보는 얼음이 있다 | `figures/real_failure_miss.jpg` | 실사진 얼음 5,640장 중 **3.2 % 를 놓친다**. 전부 무광 서리 계열, 반사도 0.00 |
| 그래서 2차 방어가 필요하다 | 같은 그림 | 놓친 사진의 얼음확률 0.01~0.09 — 문턱을 낮춰도 못 잡는다 |

> 이 그림 한 장이 이중 방어 구조의 존재 이유다. 숫자보다 사진이 강하다.

## 2. 1차 방어 — 실제로 얼마나 보는가

| 주장 | 자료 | 수치 |
|---|---|---|
| 실사진에서 블랙아이스를 96 % 맞힌다 | `정리/05`, `figures/real_confusion.jpg` | 25,140장, 블랙아이스 **96.0 %** |
| 오분류 대부분은 안전과 무관하다 | `정리/07` | 안전 영향 오분류는 전체의 **1.24 %**. 나머지 11.3 % 는 거칠기 등급 혼동 |
| 운영점이 근거 있게 정해졌다 | `figures/real_threshold.jpg`, `정리/05` | 문턱 0.60 에서 얼음 96.8 %, 젖음 1.9 %, 포트홀 0.5 %, 정상 0.4 % |
| 시뮬이 아니라 실물이다 | `demo_실사진주행_split.mp4` | 실사진 100장을 보드가 실시간 판정. 빙판 구간 34프레임 중 33프레임 경보 |

> **하지 말 것**: "시뮬에서 몇 % 인식" 이라고 말하는 것. 시뮬 정상 탐지 risk 중앙값(0.515)이
> 오경보(0.560)보다 낮아 두 분포가 겹친다. 지각 성능은 실사진으로만 말한다.

## 3. 2차 방어 — RTOS 가 왜 필요한가 ⭐ (대회 주제의 핵심)

| 주장 | 자료 | 수치 |
|---|---|---|
| 범용 OS 는 깨어남부터 늦는다 | `정리/06` | Pi 5 리눅스 1 ms 주기 태스크가 **유휴에서도 최대 4.7 ms** 늦게 깨어남 = 제어 주기의 23 % |
| 보드는 유계다 | `정리/06`, `logs/board_wcet.jsonl` | 깨어남·연산·응답 합쳐 **16.2 µs**, 주기의 0.08 %. 14,162 샘플 |
| 우선순위 선점이 실제로 동작한다 | `정리/06` §3 | NPU 가 25.5 ms 추론 중에도 2차 응답 10.9 → **12.5 µs** (+1.5 µs). 선점 없으면 25,500 µs |
| 이 배치가 **필요조건**이다 | `정리/10`, `figures/schedule_inverted.jpg` | 뒤집으면 IMU 응답 25.56 ms > 마감 20 ms → **스케줄 불가능** |
| 스케줄 가능성이 증명된다 | `정리/10` | U = 0.6395 ≤ 0.8284 (RM 충분조건). 응답시간 분석도 통과 |
| 설계 여유가 있다 | `정리/10` §5 | 카메라 한계 약 39 fps (NPU WCET 25.55 ms 가 바닥) |

> 그림 두 장(`schedule_rtos.jpg` / `schedule_inverted.jpg`)을 나란히 띄우면 설명이 거의 필요 없다.

> **하지 말 것**: "보드가 Pi 보다 빠르다" (연산은 Pi 가 156배 빠르다),
> "리눅스로는 불가능하다" (PREEMPT_RT 로 가능하다 — **복잡도** 논거로 말해야 한다).

## 3-2. 2차 방어는 얼마나 빨리 잡나 — 분포로 말하기 ⭐

| 주장 | 자료 | 수치 |
|---|---|---|
| 한 번 잰 값이 아니다 | `정리/11` | 15 주행. 빙판 진입 → 미끄러짐 확정 **1.10 ~ 5.00 s** (평균 2.37) |
| 보드 응답은 조건과 무관하다 | `정리/11` | 최악 13.9 ± 1.0 µs — 15 주행 내내 좁다 |
| **빠를수록 빨리 잡는다** | `정리/11` §4 | 45 km/h 1.10 s · 40 km/h 1.78 s · 35 km/h 4.23 s |
| 그 이유를 안다 | `정리/12`, `정리/13` | 요구 횡가속도가 v²/R. 저속은 잔차가 임계에 **4 % 차이로** 못 닿는다 |
| 그래서 고쳤다 | `정리/13`, `정리/14` | 판정을 직사각형(OR)에서 **타원**으로. 늦어질 수 없고 오탐은 480 시행 0 |

> **하지 말 것**: `정리/11` 의 충돌 7/15 를 "실패율"로 말하는 것. 정차 차량을 빙판 중심 +45 m —
> 빙판 위 정지거리보다 짧은 곳 — 에 일부러 세워 회피를 강제한 배치다. 최악 조건의 스트레스 값이다.
> 게다가 3 건은 이미 정지한 뒤 1~4 km/h 로 닿은 접촉이다. 표에서 둘을 갈라 놨으니 그대로 쓰면 된다.

> **하지 말 것**: 시드 5종을 표본 5개로 세는 것. `--ice-seed` 는 주변 차량 배치와 얼음 외관만 바꾸고
> 자차 주행선은 안 바꾼다. 같은 속도에서 독립 표본은 사실상 1개고, 나머지는 앞차와 얽힌 경우다 (`정리/11` §7).

## 4. 이중 방어가 실제로 작동하는 장면

| 장면 | 자료 | 내용 |
|---|---|---|
| 1차가 잡는다 | `정리/A_1차방어_카메라인식_정지/` | 빙판 23 m 앞 정지 |
| 1차가 놓치면 2차가 받는다 | `정리/B_2차방어.../` | 진입 → 1.78 s 미끄러짐 확정 → 비상 제어 → 정지 |
| **1차가 스스로 물러난다** ⭐ | `demo_HardRainNoon_detect.log` | 강수 21.8 mm/h → "1차 방어 신뢰 불가 → 끄고 2차에 맡긴다" → 2차가 11.34 s 에 정지 |
| 제어기가 상황을 판단한다 | `demo_ClearNoon_evade_lead30/45` | 앞차 69.6 m 면 차선유지·정지, 49.6 m·36.9 m 면 **회피** |
| 방어가 없으면 | `정리/F_방어없음_기준선/` | 이탈 12.02 s → 스핀 14.72 s → (주변차량 있으면) 충돌 |

> ⭐ 표시가 이번에 새로 확보한 장면이다. "1차가 완벽하다" 보다 "1차가 못 하는 조건을 알고
> 그때 2차가 받는다" 가 훨씬 방어하기 쉽다.

## 5. 공학적 성숙도 — 심사가 볼 것

| 주장 | 자료 |
|---|---|
| WCET 를 추정이 아니라 **측정**했다 | `logs/board_wcet.jsonl` — 주행마다 덧붙는 누적 로그, 14,162 샘플 |
| NPU 비용이 **결정적**이다 | `정리/05` — 25.49 ms, 편차 0.13 ms (평균의 0.5 %), 25,140 회 |
| 오경보율을 **실측**했다 | `정리/01` — 빙판 없는 대조군 10건 |
| 센서가 없어도 **검증 계획**이 있다 | `정리/09` — IMU 노이즈 예산 200 mg RMS, 일반 MEMS 대비 133배 여유 |
| 기상에 **적응**한다 | 본문 §9 — 날씨마다 문턱·가중치가 달라진다 (0.585~0.609, β 0.15~0.45) |

## 6. 먼저 말해야 하는 한계

심사에서 나올 반론은 대부분 이 다섯 가지다. **먼저 말하는 쪽이 낫다.**

| 한계 | 어떻게 말할까 |
|---|---|
| 시뮬 인식률은 쓸 수 없다 | "지각 성능은 실사진 25,140장으로 말합니다. 시뮬은 시스템 타이밍의 증거입니다" |
| 날씨별 2차 결과는 표본 1이다 | "CARLA 날씨는 물리에 영향을 주지 않습니다. 그래서 시드·속도·마찰을 흔들어 따로 쟀습니다" (`정리/11`) |
| 기준선 충돌은 재현 보장이 아니다 | "제어 상실(이탈 12.02 s·스핀 14.72 s)은 매번 같습니다. 충돌 여부는 주변 차량 위치에 달렸습니다" |
| 폭우에서 1차를 못 믿는다 | "압니다. 그래서 시스템이 스스로 끄고 2차에 맡깁니다" — 약점이 아니라 설계다 |
| 실물 IMU 노이즈 미측정 | "허용 예산을 먼저 정했습니다. 센서를 붙이면 정지 10분 로그 한 번으로 확정됩니다" |
| 저속에서 2차가 느리다 | "압니다. 원인이 판정 형태였고 고쳤습니다" — `정리/12`·`13`·`14` 를 그대로 보여준다. 약점을 찾아 고친 기록이 있다는 게 더 강하다 |
| 타원 규칙이 보드에 아직 없다 | "코드는 들어갔고 C↔파이썬 동치도 통과했습니다. 굽는 데 BOOT1 스위치 물리 접근이 필요해서 다음 현장 작업 때 반영합니다" |
