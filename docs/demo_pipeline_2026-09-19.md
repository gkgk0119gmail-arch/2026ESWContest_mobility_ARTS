# 데모·검증 파이프라인 기록 (2026-09-19 밤)

노션 계획(`dataset/team/notion/경진대회.md`)과 맞춰 정리한다. 1/5 차량 실빙판 실측은 무리라는 판단에 따라
**실물 보드(STM32N6 NPU + ThreadX) + CARLA 물리의 HIL 검증**을 3단계로 삼고, 실물 데이터는 RSCD 실제 사진
인-더-루프 평가로 보강한다.

## 구조 (실제 구현)

```
CARLA (데스크탑)  ─ 카메라 ROI(int8) ─▶ Pi 브리지 ─UDP─▶ STM32N6  NPU 추론(25 ms) + 위험도 융합  ─▶ 1차 경고 → 제동
                 ─ IMU + 차선오차 + 주변차 간격 ─▶ Pi 브리지 ─UDP─▶ STM32N6  ThreadX 융합 스레드:
                                                                   칼만 필터 미끄러짐 감지(횡가속·yaw·저마찰) → 비상 제어
                                                                   (차선 유지 + ABS 펄스 / 빈 차로 회피 / 최대 제동)  ─▶ 매 샘플 명령
```
- 학교망이 유선→무선을 막아 데스크탑이 bind, Pi가 connect (ZMQ 방향 역전). 보드는 Pi 사설망에만 있다.
- 2차 방어 C 코어: `fw/npu_lib/slip_core.h` (파이썬 참조 `src/icepredict/pi/imu_slip.py`와 동치 검증 `fw/npu_lib/test_slip_core.py`).
- 패킷: 60 B 요청(`<I13fI`) / 28 B 응답(`<IBBBBffIff`, emerg·mode 포함). 펌웨어 패치 `fw/npu_lib/patch_fw_slip.py`, 재배포 `scripts/deploy/fw_redeploy.sh`.

## 오늘 확인된 사실
- 40 km/h: 맑음·젖음·흐림·해질녘·젖은흐린해질녘·보슬비에서 카메라가 인식해 빙판 24~40 m 앞 정지.
- 오경보: 폭우·밤 배경은 정지 상태/ROI 밖(빙판 45~65 m)에서 위험도 0.5 안팎으로 경고 → 모델이 어두운/비 오는 노면을 얼음으로 봄. 비 오는 밤은 진입 뒤에야 경고(경고 늦음).
- 60 km/h: 경고가 빙판 12 m 앞에서 나와 41 km/h로 진입 → 2차 방어 필요.
- 2차 방어(보드): 미끄러짐 확정 시각이 파이썬 참조와 동일, 보드 판정 35.7 µs(감지만)/75 µs(제어 포함), 주변 차량 회피 evade_right 동작 확인.
- RSCD의 ice 클래스는 다져진 눈·서리 질감이라 투명한 블랙아이스와 다르다(노션 '냉정한 한계'와 일치).

## 추가 발견 (22:56) — 2차 방어 오탐과 조향각 모델
주변 차량이 있는 인식 주행에서 빙판 도착 전 마른 노면에서 2차 방어가 발화했다(앞차 끼어들기 → 자율주행 급조향).
원인: 감지기(파이썬·C 동일)가 steer(-1~1)를 최대 35°로 환산하는데 CARLA 테슬라의 실제 최대 조향각은 70°다.
급조향 때 기대 yaw rate 가 절반으로 계산되어 잔차(ay_g, yaw_err)가 부풀었다. 직선 주행에서는 드러나지 않았다.
조치: 데모가 차량 물리값(`max_steer_angle`)으로 steer 를 35° 기준으로 환산해 보낸다(프로토콜 불변). 영향받은 3건은 batch_G에서 재실행.
교훈: 2차 방어의 오탐률은 **정상 회피 조향이 있는 교통 상황**에서 재야 한다 — 노션 '오탐률 측정 기준' 항목의 시나리오로 채택.

## AI ECU 관점 정리 (02:10)
STM32N6 한 보드가 **인지(NPU, 1차)** 와 **안전 반응(RTOS, 2차)** 을 함께 맡는다 — 혼합 임계도(mixed-criticality) AI ECU.
ThreadX 우선순위: IMU 융합 스레드 3 > NPU 프레임 스레드 4. 즉 25 ms 짜리 추론이 돌고 있어도 IMU 판정이 선점한다.
근거(보드가 응답에 실어 보낸 DWT 사이클 측정, v4+ 시리얼 출력 제거 후):
- NPU 추론과 동시에(1차 켜짐, 25회 주행): IMU 응답 평균 11.5 µs, 주행별 최대의 평균 14.7 µs, 전체 최대 19.9 µs
- NPU 유휴(1차 꺼짐, 16회): 평균 10.0 µs, 최대의 평균 12.2 µs, 전체 최대 13.6 µs
→ 추론 부하가 HI-CRIT 경로에 더하는 지연은 수 µs. 노션의 'HI-CRIT 응답 WCET 측정' 항목의 실측치로 쓸 수 있다.
다음 단계(AI ECU 완성도): (1) 카메라 경로 하트비트 — 추론 응답이 N ms 이상 끊기면 보드가 '인지 경로 저하' 플래그를 세우고 2차만으로 운행 표시,
(2) 워치독으로 IMU 스레드 지연 감시, (3) HI/LO 스택·메모리 분리 문서화.
